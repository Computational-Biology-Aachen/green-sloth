# ADR 0002: `model.ts` as Authoring Source, `.mxl.json` as a Parity-Gated Generated Artifact

**Status:** Implemented
**Scope:** `scripts/generate-mxl.ts`, `src/lib/models/*/model.ts`,
`src/lib/models/*/model.mxl.json`, `$lib/loadModel`

---

## 1. Context

Each model has a hand-authored `model.ts` (using `mxlweb-core`'s builder API) and a
committed, generated `model.mxl.json` sitting next to it. The app loads the `.mxl.json`
at runtime (`$lib/loadModel`), not `model.ts` directly. `generate-mxl.ts` regenerates
the JSON from the TypeScript source and must be re-run whenever `model.ts` changes.

Critically, `generate-mxl.ts` runs under `vite-node` so `mxlweb-core` resolves via its
`svelte` export condition to `src/` — the same resolution the app itself uses — so the
emitted JSON matches what the app would actually build, not a possibly-stale `dist/`.

The script gates each model on **codegen-artifact parity**: it builds the model both
from `model.ts` directly and from the JSON it just emitted (via `mxlJsonToModel`), and
asserts the two produce byte-identical simulation code (RHS, derived quantities, names,
initial/parameter values, LaTeX). A model that fails this gate is skipped — its `.ts`
still ships, but the committed JSON isn't updated — and the script exits non-zero.

## 2. Decision

Author models in TypeScript (`model.ts`); treat the committed `.mxl.json` as a build
artifact of that source, regenerated by a script that refuses to update the artifact
unless it can prove the round-trip is lossless.

## 3. Rationale

Running at the app's own module resolution (`src/` via the `svelte` condition, not
`dist/`) means the generated JSON is guaranteed to reflect what the running site
actually builds — not an artifact that could silently diverge from a stale compiled
`mxlweb-core`.

The parity gate exists because the whole point of `.mxl.json` is that it's what
end-user contributions (see [ADR 0003](0003-issue-to-model-contribution-pipeline.md))
and the runtime loader consume — a silent lossy conversion from `model.ts` to JSON would
mean the site simulates a *different* model than the one reviewed in the contributor's
PR. Byte-identical codegen comparison is a strong, mechanical way to catch that class of
bug before it's committed, rather than trusting the conversion by inspection.

## 4. Consequences

- Never hand-edit a `model.mxl.json` — it's a build artifact. Edit `model.ts` and rerun
  `npm run generate:mxl`.
- If a model fails the parity gate, that's a real bug in either `model.ts` or the
  generator — not something to route around by hand-patching the JSON.
- This same "generate against `src/`, not `dist/`" resolution trick matters for anyone
  debugging why a locally-generated JSON doesn't match what's already committed.
